# Rendered screen criteria

Use the product's design system and the user's intended task to judge what needs to change.

- Check hierarchy, neighboring states and responsiveness. When overflow is suspected, compare the document's scroll width with its client width and locate the element causing the issue.
- Measure contrast against the rendered background and check touch target size and spacing. Apply the project's accessibility target and the relevant WCAG criterion rather than treating one numerical threshold as universal.
- Check keyboard focus, names and control behavior where they affect access. Use accessibility inspection or an audit alongside direct observation. Test the actual interaction before claiming a user is blocked.
- Compare the reference and implementation in the same viewport, theme and state. A screenshot can support a visual finding. Use a real interaction for claims about hover, focus or touch.

[WCAG contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [WCAG target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
