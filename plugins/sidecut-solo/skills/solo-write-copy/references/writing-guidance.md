# Writing guidance

Use this with the user's chosen voice, [templates.md](templates.md) for homepage and listing copy, and [readme-shape.md](readme-shape.md) for READMEs and technical docs. For a catalogue of common machine-writing patterns, see [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing).

- **Samples beat rules.** Rules alone produce generic copy. Start homepage and listing copy from real reference pages and [templates.md](templates.md), filled with facts from the repo that owns the subject. For READMEs and docs, write directly from the code following [readme-shape.md](readme-shape.md), without marketing pitch or style rules.
- **Keep verdicts where the page lives.** Store approved and rejected lines in the repo's own voice guide so later writers do not repeat the same mistakes.
- **Prompt any writer with exact words.** Pass along the user's verdicts in their own words, the exact lines already rejected, pointers to each product's README for facts, the templates and reference pages, and keep layout references separate from copy. Say `prompt` rather than `brief` for instructions an agent acts on.
- **Deliver copy as plain text with before-and-after.** Alongside the rendered page or updated file, show the full copy as plain text in a before-and-after table so the user can judge the words directly, and keep earlier rounds' rows when iterating.
- **Start with the reader's purpose.** Put the information they need first and use details that explain what they can do or decide.
- **Read related items together.** Repeated openings, order and endings can make cards and blurbs feel templated. Give each item a structure that fits what it says. Keep consistent patterns that help people scan, such as changelog entries and control labels.
- **Give each field a job.** If the headline, summary and caption repeat a claim, say it once and use the other fields for a distinct detail.
- **Edit for meaning and rhythm.** Treat scan flags as prompts to read a passage. Keep punctuation, sentence length and emphasis that suit the user's voice and the meaning.
- **Rework the whole piece when edits conflict.** Read the feedback together, then check that the revised draft answers it in context.
