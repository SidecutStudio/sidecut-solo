# Blind bake-off

Read this when the user must see drafts to choose between them.

Use a measurable check instead when it settles the question. Keep maker identities hidden until the user ranks the entries.

## Steps

1. Freeze one brief with deliverables, copied inputs, rules and a bounded time or spending allowance. Use two to five entries.
2. Give each entry the same brief and an empty output folder. Keep makers' names out of filenames and deliverables.
3. Run independent entries where delegation is authorized. Record elapsed time, usage, cost and failures outside the gallery.
4. Shuffle outputs into lettered folders. Keep the identity key separate and remove maker names from comments, metadata and visible content.
5. Follow the shared visual-report guidance named in `solo-choose-approach`. Build one gallery showing realistic contexts, including small sizes and supported backgrounds. Embed images when adjacent published files might not load.
6. Make the page readable without scripts or browser storage. End with the entries to rank. Ask for the ranking after the gallery is visible, following `server/data/owner-input.md` from the loaded plugin root.
7. Render and inspect the gallery before sharing it. Do not rely on a form or button that the host might display as a static image.
8. Where available, obtain an independent sealed ranking from an agent that sees only the gallery. Do not open it before the user's ranking.
9. Reveal makers, time, cost, failures and both rankings together. Include the second opinion's required fixes for selected entries.

The user's ranking decides the choice. A second opinion checks it; one sample does not establish a model's general quality.

Continue into `solo-build-change` only when implementing the selected draft is authorized.
