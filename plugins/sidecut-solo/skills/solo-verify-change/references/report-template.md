# Report a saved run

Read this when turning a validated run record into a readable verification report.

Use this structure, replacing placeholders with observed evidence:

1. State the tested outcome and overall status.
2. Identify scenario ID, run ID, exact subject and environment.
3. List each check with expected result, observation, status and evidence location.
4. Describe defects with reproduction steps and affected checks.
5. List interventions, simulated behavior, unavailable checks and remaining uncertainty.
6. State the next check or action needed.

Keep raw capture paths and run records available for inspection.

Report validation separately from behavior. A correctly failed known-bad fixture demonstrates detection rather than product success.
