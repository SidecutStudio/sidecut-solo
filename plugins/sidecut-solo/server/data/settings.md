# Use the current project's settings

For a task in a Git project, resolve the target checkout and read its instructions. Run `solo config --repo REPO` as described in [helper-launcher.md](helper-launcher.md), or use `get_settings` with the checkout's absolute path. Reuse the result within the same task unless the checkout or settings change. For a task with no project, read any relevant defaults from `~/.config/solo/preferences.toml` and apply the user's instructions for the task. Standalone tasks need no project setup.

- When `setup_needed` is true, use `solo-configure-project`'s first-run flow before starting project work. Offering setup is read-only and belongs at the start of review and planning tasks too. Save settings only after consent and when the host permits edits. Load that skill directly, or read its `SKILL.md` from the installed plugin if the host has no skill invocation tool. Check the task's existing answer first so handoffs never repeat the offer.
- If the helper is unavailable, check the repository for `solo-workflow.toml` and `solo-workflow.local.toml` and the current user's `~/.config/solo/preferences.toml`. Read any that exist. Offer setup only when all three are absent in a Git checkout. Report unreadable settings and keep delivery subject to the project's checks and merge policy.
- Follow the effective settings and mention the relevant choices and sources once when applying them. Unset choices use Solo's neutral defaults and facts verified in this repository. Apply the project's own guidance without copying policies from the plugin's source repository, other checkouts or the publisher's environment.
- Optional issue-tracker, task-board and external CI integrations come from `[integrations]` or explicit instructions for this project or task. A tool being installed, a repository name or a remote owner never selects an integration. For unset or disabled integrations, leave service names out of replies and generated files. A setting of `"off"` disables that integration pending a new explicit user decision. Integration settings describe what is already used and carry no permission to change a service.
